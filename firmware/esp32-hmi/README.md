# HMI ESP32-S3 · симуляция

Полный экран LVGL 9 собирается для ESP32-S3. Профиль дисплея/касания
Waveshare Rev 1.2 также компилируется, но **на плате не испытан**.
По умолчанию приложение исполняет UI с виртуальным дисплеем, без GPIO/I²C/CAN.
Управление двигателями и реальным шпинделем отсутствует в обоих профилях.

## Сборка Ubuntu через Docker
Из корня проекта:

```sh
./tools/build_idf.sh headless
./tools/build_idf.sh rev12
```

Скрипт только компилирует: USB/порты не передаются контейнеру, flash/monitor
не вызываются. Образ ESP-IDF 5.3.2 зафиксирован по digest, прямые зависимости
закреплены в main/idf_component.yml, транзитивные — в dependencies.lock.
Результаты: build-idf-headless/ и build-idf-rev12/.
Профиль rev12 включает только экран/касание и требует octal PSRAM.
Сборка подтверждает совместимость API, а не работу физической платы.

Для локально установленного ESP-IDF 5.3.2 после export.sh:

```sh
cd firmware/esp32-hmi
idf.py -B build-headless -DSDKCONFIG=build-headless/sdkconfig build
idf.py -B build-rev12 -DSDKCONFIG=build-rev12/sdkconfig \
  '-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.rev12' build
```

Не использовать старый sdkconfig поверх другого профиля: настройки сохраняются.
Образ по умолчанию имеет минимальную разметку ESP-IDF 2 MB, single factory app
1 MB. Это параметры сборки, не определённый размер flash платы. Фактические
flash_id, PSRAM и ревизию проверить до записи; не переносить автоматически
предлагаемую сборщиком команду flash на непроверенное устройство.
Backup/rollback: docs/BOARD_VERIFICATION.md; адаптер и его источники:
docs/BOARD_ADAPTER.md; журнал сборки: docs/BUILD_VALIDATION.md.

## Проверка на компьютере

```sh
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
```

Рендеринг тем же LVGL 9.2.2, в том числе RGB565:

```sh
git clone https://github.com/lvgl/lvgl.git ../lvgl
git -C ../lvgl checkout 7f07a129e8d77f4984fff8e623fd5be18ff42e74
cmake -S . -B build-ui -G Ninja -DLVGL_DIR="$(realpath ../lvgl)"
cmake --build build-ui
ctest --test-dir build-ui --output-on-failure
```

Создаются dashboard.ppm и dashboard-rgb565.ppm в build-ui/.
Тесты проверяют состояния, отказы, кириллицу, кнопки и отсутствие перекрытий
надписей. Это не эмулятор ESP32 и не измерение FPS/касания на плате.

## Параллельность
app_main — единственный владелец LVGL. Отдельная задача опрашивает GT911
и публикует последний снимок в статическую очередь длиной 1. Обработчик LVGL
читает очередь без ожидания и не обращается к I²C. Потеря корректного касания
на 500 мс защёлкивает ошибку интерфейса. Ошибки не запускают движение.
Контрольный лог сообщает кадры, время рендера, heap и событие→обработчик;
задержка физическое касание→пиксель требует отдельного измерения.

## Ресурсы
Шрифты DejaVu, включая кириллицу Ё/ё; лицензия в assets/FONT-LICENSE.txt.
Команды lv_font_conv@1.5.3 записаны в заголовках C-шрифтов. Контурные значки:
tools/generate_icons.py. RGB565 иллюстрация: tools/prepare_photo.py,
происхождение и промпт в assets/IMAGE-PROVENANCE.md. Исходный PNG в бинарник
не включается. Навигация и часть органов управления остаются визуальными
заглушками; текущий состав — docs/UI_REFERENCE.md.

## Диагностика и журнал
Работают разделы Главная, Диагностика, Журнал. Диагностические кнопки
передают только события макета, не вызывают I²C/CAN/драйверы. Ошибки имеют
отдельные причины, ACK оставляет паузу; новая симуляция — отдельная кнопка.
История из 32 записей хранится в RAM, 8 строк на страницу, старые события
вытесняются со счётчиком. Она не сохраняется после выключения. Повтор одного
отказа в FAULT не создаёт запись каждый цикл. Детали: docs/SOFTWARE_STAGE_002.md.

## Инструмент
Рабочий раздел описан в docs/SOFTWARE_STAGE_003.md. Четыре ячейки в RAM,
черновик и клавиатура; сохранение и выбор активного разделены. Это библиотека
макета: коррекции не применяются, NVS/реальные команды смены инструмента отсутствуют.
