# Настройка Wi-Fi на HMI

План и критерии: локальный экран настройки сети, неблокирующие запросы LVGL,
STA без серверов управления станком, проверка пароля, состояния/IP и отключения,
сборка headless/rev12 на ESP-IDF 6.1.1 и 5.3.2, host-проверки компоновки и памяти.

## Использование

Откройте «Параметры» слева или шестерёнку справа сверху. Нажмите «Найти сети»,
затем выберите одну из шести показанных сетей. Список показывает SSID и RSSI.
Можно ввести SSID вручную, включая имя скрытой сети. Доступен диапазон 2.4 ГГц.
Нажатие поля открывает клавиатуру; галочка закрывает её. Пароль скрыт звёздочками.
Нажмите «Подключить»: после DHCP экран покажет «Подключено» и IPv4-адрес.
Наличие IP не является проверкой доступа в Интернет.

SSID: 1–32 байта; пароль: пустой для открытой сети либо 8–63 байта для личной
сети. Клавиатура вводит латиницу, цифры и символы. Enterprise-аутентификации
и captive portal нет. Длина проверяется по байтам, а не числу UTF-8 символов.

Для смены сети сначала нажмите «Отключить». Поиск разрешён в отключённом
состоянии, чтобы не прерывать действующее соединение. При ошибке показан код
причины драйвера; проверьте пароль/сигнал и повторите подключение вручную.
Тайм-аут ожидания подключения/IP — 30 секунд. Автопереподключения нет.

## Хранение и границы

Используется WIFI_STORAGE_RAM: пароль не сохраняется приложением в NVS,
не входит в snapshot для UI и не выводится приложением в журнал. Поле пароля
очищается после запроса подключения и при выходе из настроек. Конфигурация
текущего соединения остаётся в RAM Wi-Fi драйвера до отключения/перезапуска.
После перезапуска подключитесь снова. Обработчик ошибок NVS ничего не стирает:
ошибка инициализации отображается, заводские данные автоматически не удаляются.

Отдельная задача обрабатывает ограниченную очередь запросов. Сканирование
выполняется в ней, а не в LVGL callback. UI получает snapshot без ожидания mutex;
только владелец LVGL меняет виджеты. Инициализация Wi-Fi включена только в rev12;
headless и host не запускают радио. Host-backend честно отклоняет сетевые запросы.
Wi-Fi не меняет модель связи с motion, не разрешает движение и не поднимает
HTTP/OTA/удалённое управление. Выхода GPIO и команд CAN не добавлено.

## Разметка и проверка

Wi-Fi увеличивает приложение сверх прежнего 1 МиБ. `partitions.csv` теперь
задаёт factory app 2 МиБ с прежнего адреса 0x10000; NVS остаётся 0x9000/24 КиБ,
phy_init — 0xf000/4 КиБ. Flash по-прежнему 16 МиБ. OTA не реализовано.
Старое описание app 1 МиБ в отчёте IDF_611_COMPATIBILITY относится к предыдущей
проверенной версии, до добавления Wi-Fi. Новые размеры — в evidence/build/wifi/.
Если старый build tree сохранил single-app sdkconfig, используйте новый build tree
или перегенерируйте его конфигурацию; defaults не переопределяют старые значения.
При будущей записи нужна новая таблица разделов вместе с приложением, а не только app.

Host-тесты проверяют длины SSID/пароля, открытый пароль, пустые/слишком длинные
значения, открытие экрана/клавиатуры, очистку пароля, честный отказ host-backend
и компоновку в XRGB8888/RGB565. Сетевой драйвер, DHCP, неверный пароль, потерю AP,
потребление памяти и плавность RGB при включённом радио нужно проверить на плате.
Показания из host не являются аппаратными результатами. Эта версия не прошивалась.
Откат: восстановить предыдущие исходники и соответствующую им таблицу разделов;
полный заводской образ хранится отдельно от Git.

API: [ESP-IDF Wi-Fi driver](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/network/esp_wifi.html).
