# Адаптер дисплея Rev 1.2

## Источники
- Схема Waveshare ESP32-S3-Touch-LCD-7 V1.2:
  https://files.waveshare.com/wiki/ESP32-S3-Touch-LCD-7/ESP32-S3-Touch-LCD-7-Sch.pdf
- Официальный пример LVGL 9, фиксированный commit:
  https://github.com/waveshareteam/ESP32-S3-Touch-LCD-7/tree/bc51a84b30c0cea018fee6e0d7427ec10102060e/examples/ESP-IDF/09_lvgl_v9_demo
- GT911 1.1.3:
  https://components.espressif.com/components/espressif/esp_lcd_touch_gt911/versions/1.1.3/readme
- Адаптер нового примера требует IDF >=5.5:
  https://components.espressif.com/components/espressif/esp_lvgl_adapter/versions/0.5.2/readme

README примера ошибочно/шаблонно называет LCD ST7701; Wiki платы перечисляет
ST7262. Поэтому не используются команды инициализации ST7701. Для этой платы
используется RGB-драйвер ESP-IDF, данные и синхронизация из исходников производителя.
В текущем примере Waveshare заявлен IDF >=5.1, но подключён esp_lvgl_adapter 0.5.2,
который требует >=5.5. Наш адаптер не зависит от него и использует LVGL 9.2.2
непосредственно с RGB API ESP-IDF 5.3.2/6.1.1. Миграция на общий новый I²C bus
для GT911/CH422G и RGB DMA описана в IDF_611_COMPATIBILITY.md.

## Что подтверждено схемой
Визуально просмотрена схема с маркировкой V1.2. GPIO RGB, I²C 8/9,
IRQ 4, CH422G EXIO1 touch reset, EXIO2 backlight, EXIO3 LCD reset,
EXIO4 SD CS и EXIO5 USB select соответствуют официальному примеру.
На схеме модуль N8R8. Это не измерение объёма памяти пользовательского экземпляра.

## Поведение
По умолчанию TV4_BOARD_REV12 выключен. Процесс исполняет полный UI с виртуальным
дисплеем без GPIO/I²C/RGB/CAN. При включении стендового профиля:
- RGB 800×480, 16 MHz, 16-bit, один framebuffer в PSRAM;
- буфер перерисовки 20 строк, bounce-буфер 10 строк (API принимает пиксели);
- GT911 опрашивается отдельной задачей; UI читает статическую очередь длиной 1;
- все вызовы LVGL остаются в app_main; обработчик касания не выполняет I²C;
- подсветка включается только после построения первого кадра;
- CH422G USB_SEL удерживается низким во всех записях, CAN не включается;
- SD CS удерживается высоким. В vendor reset sequence 0x2c/0x2e временно
  выставляет USB_SEL=1; у нас запись 0x18/0x1a/0x1e этого не делает.

Не реализовано подавление разрывов кадра: один framebuffer допускает tearing.
Параметры PCLK, PSRAM и ориентацию касания нужно подтвердить на стенде.
Никаких выходов движения, CAN-передачи или управления реальным шпинделем нет.
Заводской бэкап 16 МиБ завершён и проверен по SHA-256: BACKUP_STATUS.md.
Вывод HMI на плате подтверждён фотографиями владельца; параметры/полный
тест GT911, FPS, touch-to-display и восстановление бэкапа ещё не подтверждены.
Актуальная граница доказательств — [HARDWARE_STATUS.md](HARDWARE_STATUS.md).

Ошибки касания/дисплея поступают в модель отдельными событиями, имеют
различимые причины и попадают в журнал RAM; диагностика не выполняет I/O.
