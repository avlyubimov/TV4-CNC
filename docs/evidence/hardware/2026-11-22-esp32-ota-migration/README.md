На изолированной Waveshare ESP32-S3-Touch-LCD-7 Rev 1.2 выполнен отдельно
разрешённый стенд `fecc05d676a0b1e3376db5317fa241274e8e310a`, `rev12-ota`,
ESP-IDF 6.1.1. База отчёта — main `c41a3d24bbca9f6c55015de9431dcef32651cd92`

[Машиночитаемый итог](summary.json), [16 очищенных диагностических срезов](diagnostics.json).
Сырые UART-журналы, идентификатор платы и контрольное чтение NVS/PHY приватны.

## Что проверено на плате

- Перед записью совпали ожидаемые ESP32-S3/chip ID 9, Flash 16 МиБ и защита:
  flags 0, Secure Boot/Flash Encryption отключены. Legacy partition bytes и MD5
  прежнего приложения совпали со свежим проверенным снимком `8f0d899`.
- Официальный esptool 5.6.0 использовал RAM stub, 460800 baud. Записаны только
  четыре области утверждённого пакета; `erase-all`, `force`, encrypted writes,
  eFuse и команды STM32/CAN/движения не использовались. Стирание нужных секторов
  выполнялось штатным SDK writer в пределах этих записей.

| Область | Адрес | Записано байт |
|---|---|---|
| bootloader | 0x0 | 20720 |
| partition table | 0x8000 | 3072 |
| factory recovery app | 0x10000 | 1597984 |
| пустая otadata | 0x210000 | 8192 |

- Каждая запись проверена MD5 устройства, затем выполнена отдельная MD5-проверка
  всех четырёх файлов. Таблица дополнительно прочитана и побайтно сопоставлена;
  otadata прочитана как 8192 байт FF. NVS/PHY `0x9000..0xffff` побайтно одинаковы
  в контрольных чтениях до записи и после verify, **до запуска приложения**.
  Их содержимое не декодировалось. Обычное приложение после запуска может
  законно менять NVS; неизменность после загрузки этим тестом не утверждается.
- Установлена карта `tv4-16m-ab-v1`: factory 2 МиБ, otadata, два OTA-слота по
  3 МиБ, resources/store; [точные адреса](../../../ESP32_OTA_INSTALLATION.md).
  Данные в OTA/resources/store не записывались и не объявляются очищенными.
- После reset штатный bootloader загрузил factory с `0x10000`. UART подтвердил
  `fecc05d`, SDK v6.1.1, физические 8 МиБ PSRAM, SDK memory test OK и оба сообщения
  о копировании instructions/rodata в SPIRAM. RGB 800×480 и GT911 инициализированы,
  `UI ready: LVGL 9.2.2`, draw buffer 32000 байт.
- Один UART-захват длился 89,114 с, получено 19800 байт. В нём одна app-загрузка,
  нет panic/abort/watchdog/reset loop или ошибки свежести GT911. 16 диагностических
  срезов имеют возрастающий uptime 7330–82404 мс, `watchdog_boot=0`, ошибки
  дисплея/сенсора и потери очередей равны нулю. Wi-Fi: одна попытка, один IP event,
  ни одного disconnect. SSID/IP/пароль и сырые сетевые журналы не публикуются.
- Владелец подтвердил главный экран, касания и подключение Wi-Fi с сохранённым
  паролем; на странице «ПО и обновления» требуется настройка, проверка и
  установка недоступны. Ключ/context не добавлялись, SNTP/HTTPS/OTA-install
  в этом профиле не вызывались.

## Измерения памяти и их пределы

Ниже диапазоны **16 периодических срезов**, а не непрерывная трасса пиков и
не утверждённые минимальные пороги для installer. Единицы — байты.

| Метрика | Наблюдение |
|---|---|
| Internal free | 22851–22907 |
| Internal largest block | 7680 |
| SDK internal historical minimum | 112 |
| PSRAM heap total после XiP | 6865688 |
| PSRAM free | 6090732 |
| PSRAM historical minimum | 6076588 |
| Main owner stack watermark | 10708 |
| Touch worker stack watermark | 2504 |
| Wi-Fi worker stack watermark | 1104 |
| Export worker stack watermark | минимум 1104 |

**112 байт требуют разбора бюджета до включения configured installer.**
`heap_caps_get_minimum_free_size` в закреплённом SDK суммирует исторические
минимумы отдельных heaps; это не одновременный замер доступного остатка.
Причина такого значения и пик во время startup по этим срезам не установлены.
Не следует ни объявлять доказанный OOM, ни принимать это за достаточный запас.
Нужны ограниченные измерения по фазам и рабочему сценарию без уменьшения DMA
reserve, TLS records, framebuffer или ослабления проверок. OTA-worker watermark
в этих данных отсутствует; прежний HEAD bench не задаёт production floors.

`render_samples`, `lvgl_refresh_hz` и `event_samples` в срезах равны нулю.
Это не тест FPS или отзывчивости: нагрузочный сценарий не задавался,
hardware scanout, CPU usage и touch-to-display остаются `null`/не измерены.
Touch data age 1–17 мс — свежесть выборки, не задержка касания до изображения.
Owner wall-time duty 7–9‰ и максимальный участок до 490 мкс не являются
загрузкой CPU или доказательством worst-case performance.

## Инженерные выводы, не отдельные измерения

Наблюдённое владельцем состояние SETUP соответствует успешному прохождению
factory health/256-byte PSRAM/layout self-test по переходам существующих
`ota/service.c` и `ui/firmware_view.c`. Явного UART-маркера self-test в этой
сборке нет. Это вывод из состояния UI и кода, **не** проверка подтверждения
образа в состоянии `PENDING_VERIFY` или аппаратного rollback.

Условное восстановление не потребовалось и не выполнялось. Снимок всей прежней

отдельно. Restore обоих образов ESP32 по-прежнему не испытан.

Открыты: owner key/SemVer/time/resource context, реальный download/write в
неактивный слот, подтверждение после reboot, rollback, потеря Wi-Fi/питания,
PSRAM/stack под TLS и нагрузкой, FPS/tearing/latency/soak, recovery после
прерванной начальной миграции. Базовая миграция и запуск не закрывают P1 целиком.
Новые аппаратные операции требуют нового применимого разрешения владельца;
eFuse, STM32 option bytes, CAN и motion этим результатом не разрешаются.
