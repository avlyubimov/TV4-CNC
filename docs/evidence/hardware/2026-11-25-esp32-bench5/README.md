## Почему приёмка остановлена

В `.5` наблюдались правильные version/ELF/OTA1 offset, RGB/GT911/PSRAM,
событие Wi-Fi/IP и `boot_self_test checks_pass=1 sdk_finish=1`. ROM сообщил
`rst:0x10 (RTCWDT_RTC_RST)`, а диагностика SDK — reset_reason=7 и watchdog_boot=1
во всех 17 периодических отсчётах. Остальные счётчики ошибок равны нулю,
возраст touch sample ≤4 мс. Строгая проверка `resource_errors_clear` дала FAIL.
Успех встроенного self-test не отменяет независимую проверку watchdog.

Независимое чтение Flash/otadata кандидата и финальное полное чтение Flash
не выполнялись: сценарий остановлен на этом отказе. SDK finish не выдаётся за
независимо считанное VALID-состояние или полный readback нового образа.

После отказа выполнена ровно одна разрешённая попытка возврата всех 16 МиБ из
свежего снимка. SDK проверил digest всего образа; наблюдение прежнего bench.4
подтвердило boot/ELF/health PASS. В составе полного возврата исходными байтами
также перезаписаны bootloader, таблица разделов и factory. Общий сеанс занял
1004,573 с при лимите 2400 с. После восстановления отдельного повторного чтения
всех 16 МиБ через UART не было. Исходные две NVMe-копии и factory сохранены.

## Факты, предположения и следующий шаг

Функции `esp_restart_noos`, `esp_system_reset_modules_on_exit` и
`rtc_clk_cpu_set_to_default_config` в прежней и новой принимающих ELF находятся
в IRAM с одинаковыми адресами и байтами. Hashes приведены в measurements.json.
Это сравнение не доказывает исправность всего shutdown, другого ядра, DMA,
caches или раннего boot ROM.

Причина RTC watchdog не установлена. Один reset code не позволяет связать её
с воспроизводимой сборкой, RGB DMA или ошибкой кандидата. Прежний успешный
перезапуск дал ROM0xc; это другой firmware run. Первоначальный FAIL сохраняется.

Следующий измеримый шаг — отдельный диагностический образ, выключенный по
умолчанию: первый запуск и один software restart при той же HMI/Wi-Fi нагрузке,
короткие маркеры ядра и этапов shutdown, без сетевого INSTALL. Сначала сборки
на обоих SDK, программные проверки и CI; затем точный конечный аппаратный пакет.
Проверку watchdog не ослаблять и счётчик не обнулять. Драйверы до локализации
сбоя не менять по предположению.

Потеря RF/AP/питания, production policy/бюджет/поиск версий, runtime 5.3.2 и
физические FPS/latency остаются открытыми. STM32, CAN, движение, eFuse и option
bytes не затрагивались. Дампов, сырого UART, ключей или контекстов в отчёте нет.
