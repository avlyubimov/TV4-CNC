# Первая configured trace: отказ контроля, возврат bench.4

26 ноября 2026, source `2cae6c44d9115873eee3fbd93c17281f4caf6866`, SDK 6.1.1.
[Числовые данные](attempt1.json). Сеанс закрыт за696.950 с при лимите3300 с.

Свежие16МиБ действительно считаны за385.4 с, прошли device verify/SHA-256;
две копии на разных физических NVMe проверены до записи. Временный receiver
записан только в OTA0[0x220000,0x520000), выбор — первые4КиБ otadata.
Каждая обычная запись прошла verify и сравнение Flash вне её точного диапазона.

90-секундный контроль дал37/37 базовых boot/resource/touch guards PASS,
boot self-test и `stage=armed ready=1` наблюдались. Однако отдельный обязательный
стартовый маркер оказался перемешан с параллельным SDK log:
`tv4_restart stage=boot reset=W (981 core=0 operator=1`.
Его reset reason не восстанавливается догадкой; целевой trace qualification FAIL.
CHECK, SNTP, HTTPS и INSTALL не запускались. Post-INSTALL RTCWDT в этом
сеансе не исследован и не считается исправленным.

Выполнена ровно одна предусмотренная полная запись свежего снимка16МиБ,
включая исходные bootloader/table/slots/metadata, с device verify. Новое полное
финальное чтение16МиБ не выполнялось; результат восстановления опирается
на verify записанного снимка и финальный UART30 с health PASS. Порт закрыт,
оставлен bench.4 OTA1 VALID. Владелец после закрытия подтвердил главный экран,
касания и Wi-Fi. Приватные дампы и сырой UART сохранены, не опубликованы.

Исправление source `8b3db2f62584267e9e00f372d65b95c8029cdfe1` переводит только
стартовый trace на штатный сериализованный ESP logger. Финальные hook/noos
остаются IRAM/DRAM/ROM, без logging locks. Actual C SDK-boundary и оба настоящих
ELF проверяют этот выбор; повреждённая строка по-прежнему отклоняется.
Новый образ и новый конечный пакет проверяются отдельно; закрытый пакет
2cae6c4 повторять нельзя. eFuse/option bytes, STM32, CAN, приводы и питание
не затрагивались; новый release/tag не создавался.
