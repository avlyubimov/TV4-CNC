# Waveshare Rev1.2: один software restart без OTA INSTALL — PASS

25 ноября 2026, ESP-IDF 6.1.1, source `f8199557def895f301cd7e0cbbdde32e54b87681`.
Код [PR #93](https://github.com/avlyubimov/TV4-CNC/pull/93) слит владельцем;
[сборки и программные проверки](../../build/esp32-restart-diagnostics/README.md).
[Числовой результат](measurements.json). Сеанс закрыт за 1103.269 с
при пределе 1800 с. Новый бинарный релиз не публиковался.

На изолированной ESP32-S3 выполнен один автоматический программный перезапуск
из прежнего OTA-worker после self-test и 45 секунд ожидания. Наблюдались ровно
два запуска того же диагностического factory-приложения, второй — SW reset(3),
watchdog_boot=0. После него UART оставался открытым 90.004 с
без промежуточного host reset. Второй автоматический перезапуск запрещён и
не наблюдался. Все 36 независимых boot/resource/touch guards на каждом запуске PASS.

Инициализация RGB, GT911, PSRAM 8 МиБ, SDK memory test, PSRAM instructions/rodata,
HMI readiness и подключение Wi-Fi подтверждены UART. Счётчики ошибок сенсора,
дисплея, очередей и export — 0. Это диагностическая свежесть, не физическая
touch-to-display latency или FPS; визуальная работа экрана оператором не наблюдалась.

Маркеры показали boot на core1, request и shutdown_hook на core0,
noos на core1; после сброса boot core1, eligible=0. Перед request:
internal119487/largest63488, PSRAM5982280/largest5898240,
stack10704 байта. Вызван исходный SDK reset, защиты не перенастраивались.
Пороги перед request 64/32 КиБ internal, 1 МиБ/128 КиБ PSRAM и 3072 stack
сохранены. Исторический global heap minimum 52080 байт включает прежние фазы;
он не подменён текущим free или минимумом отдельного окна. Boot-window samples
закончились до Wi-Fi IP, поэтому отдельный BOOT Wi-Fi budget не квалифицирован.

## Flash и завершение

Перед записью все 16 МиБ реально считаны; device verify, SHA-256 и две копии
на разных физических NVMe проверены. Обычные записи хоста — только временный
factory2 МиБ и otadata8 КиБ, затем полные исходные байты тех же областей.
Каждая запись прошла verify и сравнение остальной Flash до запуска приложения.
Bootloader, таблица разделов и оба OTA-слота хостом не записывались.

После возврата все 16 МиБ заново реально считаны и проверены. Все байты вне
NVS `[0x9000,0xf000)` совпали со свежим исходным снимком, включая исходные
метаданные VALID и весь bench.4. Финальные две NVMe-копии проверены.
Полное аварийное восстановление не понадобилось: 0 попыток.
Bench.4 оставлен в OTA1 VALID, финальная UART-проверка 30 секунд PASS,
подключение Wi-Fi наблюдалось; порт закрыт. После закрытия сеанса владелец
подтвердил главный экран, касания и Wi-Fi на возвращённом bench.4.

## Инженерный вывод и оставшиеся блокеры

В этом одном unprovisioned factory-сеансе RTC watchdog не воспроизведён.
Это подтверждает работу самого диагностического пути в наблюдавшихся условиях,
но не исправление или локализацию причины
[прежнего отказа bench.5 после OTA](../2026-11-25-esp32-bench5/README.md).
Наличие маркеров может менять тайминг. Не проверены настроенный context,
предшествующие SNTP/HTTPS/Flash writer, смена слота и post-INSTALL shutdown.

Следующий отдельный результат P1 — сопоставимые shutdown-маркеры в реальном
настроенном пути после подписанного CHECK/INSTALL с прежними TLS/signature/
SHA/compatibility/resource/time/confirmation guards. Сначала получить проверенный
образ и ограниченный пакет, затем отдельно квалифицировать reset/slot/self-test/
независимое чтение кандидата. Не повторять закрытые пакеты и не менять опубликованные
assets. Не снижать пороги и не обходить watchdog ради PASS.

SDK5.3.2 проверен компиляцией и фактическим ELF, не на плате. Production policy,
бюджет, RF/AP/power loss и физические FPS/latency остаются открытыми.
Нет сетевых CHECK/INSTALL/SNTP/HTTPS, отключения питания, изменения eFuse/option
bytes, доступа к STM32/CAN/приводам или нового release/tag. Физическая E-stop
цепь независима от ПО. Дампы/NVS, SSID/IP/MAC, ключи/context и сырой UART приватны.
