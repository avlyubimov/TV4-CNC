## Критическое расхождение памяти
На одной странице Wiki встречаются 16 MB в описании и 8 MB в таблице;
в тексте схемы модуль N8R8. Нельзя выбирать размер flash по названию товара.
Для пользовательского экземпляра получен полный образ 16 МиБ; это разрешает
неопределённость flash в конфигурации. Физическая PSRAM и различия ревизий
ещё требуют проверки при отдельном стендовом запуске.
Кандидаты для интеграции: ESP-IDF 5.3.2 и LVGL 9.2.2. На раннем этапе проверялась только host-сборка; теперь выполнена компиляция
обоих ESP-IDF профилей 5.3.2/6.1.1. Это не доказательство работы на плате.

## Backup перед любой прошивкой
Ниже общая процедура для отдельного стенда. Уже сохранён один полный бэкап
16 МиБ с совпавшим SHA-256; повторное независимое считывание и тест
восстановления здесь не утверждаются.
Использовать UART USB, отключить станок/приводы. Подтвердить порт по журналу ОС.
В окружении ESP-IDF 5.3.2 определить устройство и память:

```sh
python -m esptool --chip esp32s3 --port "$PORT" chip_id
python -m esptool --chip esp32s3 --port "$PORT" flash_id
```

Проверить security/eFuse: при шифровании flash/secure boot остановиться и отдельно
проверить процедуру восстановления. После подтверждения объёма установить FLASH_BYTES
(не копировать значение по догадке), считать полный образ дважды:

```sh
python -m esptool --chip esp32s3 --port "$PORT" read_flash 0 "$FLASH_BYTES" factory-a.bin
python -m esptool --chip esp32s3 --port "$PORT" read_flash 0 "$FLASH_BYTES" factory-b.bin
cmp factory-a.bin factory-b.bin
sha256sum factory-a.bin factory-b.bin
```

Сохранить вне репозитория образ, хеш, вывод flash_id, версии инструментов, фото ревизии
и настройки загрузки. Не выполнять erase_flash. Восстановление при подтверждённых
настройках загрузки и отсутствии ограничений безопасности:

```sh
python -m esptool --chip esp32s3 --port "$PORT" write_flash 0 factory-a.bin
python -m esptool --chip esp32s3 --port "$PORT" verify_flash 0 factory-a.bin
```

Затем перезапуск и проверка заводского экрана/касания. Запись не выполнялась.
